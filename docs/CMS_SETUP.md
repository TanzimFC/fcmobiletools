# TanzimFC CMS setup

Phase 1 uses the existing Cloudflare Workers Builds pipeline. A push to `main` runs `npm run build` and then `npx wrangler deploy` in the connected Worker build configuration.

## Required Worker secrets

Set these in Cloudflare Worker Variables and Secrets. Do not add their values to GitHub.

- `CMS_SESSION_SECRET`: long random secret used to sign admin sessions
- `CMS_USERS_JSON`: JSON array of admin accounts with PBKDF2 password hashes
- `GITHUB_TOKEN`: GitHub fine-grained token for `TanzimFC/fcmobiletools` with the minimum repository Contents write permission needed by the CMS
- `CLOUDINARY_CLOUD_NAME`
- `CLOUDINARY_API_KEY`
- `CLOUDINARY_API_SECRET`

Example `CMS_USERS_JSON` shape, with the password hash generated by the helper script:

```json
[
  {"username":"owner","displayName":"TanzimFC","role":"owner","passwordHash":"pbkdf2$210000$...$..."},
  {"username":"editor1","displayName":"Editor","role":"editor","passwordHash":"pbkdf2$210000$...$..."},
  {"username":"writer1","displayName":"Writer","role":"writer","passwordHash":"pbkdf2$210000$...$..."}
]
```

Generate a hash locally with:

```bash
node scripts/cms-password.mjs "your-password"
```

The CMS accepts `writer`, `editor`, and `owner` roles only.

## Phase 1 workflow

Writer/Editor: create or edit a draft, then submit it for review.

Owner: review, reject back to draft, or approve and publish.

The API enforces these permissions. A direct API request from a writer/editor cannot publish a post.

Published posts are committed to `src/content/blog/*.md` or the existing `.mdx` file. The existing Astro blog build already exposes only `status: published` and `draft: false`, so drafts and review items do not become public pages.

Images are uploaded directly through the Worker to Cloudinary. The Cloudinary API secret remains server-side.

## Private routes

`/admin` and `/api` are handled by the Worker, not Astro. They send `noindex` headers, and `robots.txt` disallows both route families. They are not Astro pages and therefore are not added to the sitemap.

## Phase 2

Redeem-code management, media library browsing, automated article SEO metadata/structured data, and revision history remain intentionally outside Phase 1.
